# Elan Registry v2.29.6 Release Notes

**Release Date:** TBD
**Type:** Patch Release - Security Audit Closure & Browser CI

## Required Actions After Deployment

TBD — filled in as issues are completed.

## User-Facing Changes

Changes visible to public registry visitors (car listings, owner pages, search, etc.).

### Improvements

- [#1452](https://github.com/elan-registry/registry/issues/1452) — fix: non-atomic car-create — cars.image committed before files moved (root cause of #1403); a failed file move during car creation now strips the unmoved filenames from the stored image list instead of leaving the record pointing at files that don't exist
- [#1539](https://github.com/elan-registry/registry/issues/1539) — fix: bare directory URLs (`/app/owner/`, `/app/owner/reports/`, `/docs/stories/`) returned a raw 403 instead of redirecting to a useful page, and a stale redirect chain broke `/app/reports/`; also fixes a guide page's stylesheet (`document-content.css`) 404ing due to a blanket redirect that was never meant to catch it — relocated the file to `app/assets/css/` (consolidated with #1595)
- [#1850](https://github.com/elan-registry/registry/issues/1850) — perf: statistics map pins now build popup content lazily on first open (instead of eagerly for every marker) and use the `-resized-100` thumbnail instead of the full-size original photo — eliminates an unconditional full-resolution image download for every car on page load
- [#1837](https://github.com/elan-registry/registry/issues/1837) — fix: `privacy.php` and `car-transfer-faq.php` sent a redirect header to a nonexistent `403.php` on a denied `securePage()` check but never stopped execution, so the protected content rendered anyway regardless of the check's result — both now call `die()` on denial, matching the convention used by every other `securePage()`-gated page in the codebase
- [#1854](https://github.com/elan-registry/registry/issues/1854) — fix: car transfer requests that failed validation (chassis/color/engine/comments/model length, year range, malformed model, no matching car, already-owned, pending-request-exists) always returned a generic "Unable to transfer the car. Please try again." message instead of the specific reason — `transfer-request.php`'s error-throwing never set the exception's user-facing message, only its internal log message; now returns the actual reason so owners can correct their request

## Admin-Facing Changes

Changes visible only to administrators (admin dashboard, maintenance tools, settings, etc.).

### Improvements

- [#1830](https://github.com/elan-registry/registry/issues/1830) — fix: error/404.php and error/403.php silently stopped logging at v2.26.2 — bare LogCategories no longer resolves under the Composer autoloader; consolidated into error/500.php as the single handler for all 4xx/5xx codes
- [#1800](https://github.com/elan-registry/registry/issues/1800) — chore/fix: of the 4 cars identified with lost photos, car 1739's turned out not to be lost at all — an admin "duplicate merge" action correctly consolidated cars 1738/1739 in the DB but `CarAdministrationService::merge()` never moves `userimages/` files on disk, orphaning 1738's 5 photos under the deleted car (see #1867, filed to fix that gap). Recovered via a one-time fix script; cars 1049, 1455, and 1670 are confirmed genuinely unrecoverable (no matching files anywhere in production, no merge history of their own) and had `cars.image` cleared to `[]` so their pages render the placeholder instead of a 404 — owner outreach for those three still applies
- WIP: [#1689](https://github.com/elan-registry/registry/issues/1689) — fix: .git/.svn probes log as 127.0.0.1 — source-address handling makes them un-blockable and may indicate spoofable client IP

CI/test-infrastructure work, not user- or admin-facing:

- [#1829](https://github.com/elan-registry/registry/issues/1829) — tech-debt: removed the internal `Token::check()` CSRF validation from `Car::delete()` (and its now-unused `$token` parameter) — the endpoint-level CSRF check in `app/admin/index.php`, `Car::delete()`'s only production caller, already validates the token unconditionally before the delete path is reachable; mirrors the same refactor #1519/#1813 applied to `Car::create()`/`Car::update()` and clears the last internal `Token::check()` call in `usersc/classes/`, unblocking the Semgrep rule planned in #1465
- [#1788](https://github.com/elan-registry/registry/issues/1788) — test: `CAR_ID_STANDARD` in Playwright fixtures is now overridable via a `CAR_ID_STANDARD` env var (falls back to id 1), so local MAMP snapshots with different car-id numbering no longer skip or fail fixture-dependent tests
- [#1765](https://github.com/elan-registry/registry/issues/1765) — test: removed a stale `ajax-endpoints.spec.js` test referencing a Google Maps XML endpoint deleted during the MapLibre migration; the other finding (a CSRF check discrepancy) had already been resolved as a side effect of an unrelated PR (#1790)
- [#1253](https://github.com/elan-registry/registry/issues/1253) — test: added local Playwright coverage for `privacy.php`, `user_settings.php`, and the unverified-state path of `verify.php` (`contact/owner.php` landed separately via #1585); the "verified" success-path for `verify.php` is deliberately deferred, no DB fixture exists for it yet
- [#1781](https://github.com/elan-registry/registry/issues/1781) — bug: `factory-registry-link.spec.js`/`logged-in.spec.js` self-gated on a `logged-in` Playwright project that never existed locally, so both files silently 0-collected under every local run; added a `setup`+`logged-in` project pair to `playwright.config.js` (auto-authenticates via `TEST_USERNAME`/`TEST_PASSWORD` — the setup step skips cleanly if unset, though the test files themselves then run unauthenticated rather than skipping individually), fixed a `testMatch` regex gap that also excluded `factory-registry-link.spec.js` from the deployed `prod`/`test` configs, and fixed eight latent bugs the files' first-ever local run exposed (leading-slash `goto()` paths, a DataTables 1.x-only selector, nav locators targeting nonexistent `<nav>`/`<header>` tags, a hardcoded-prod URL in a link checker, a missing fixture-gap skip, a wrong account-page URL masking that same skip, and a `storageState` ENOENT crash on missing credentials) — both files now run and pass locally
- [#1852](https://github.com/elan-registry/registry/issues/1852) — test: `ajax-endpoints.spec.js`'s "DataTables AJAX endpoint returns car data" test never included a CSRF token in its POST to `app/api/cars/list.php`, which has required one since the endpoint's creation (PR #1076) — not a recent regression; fixed by reusing the file's own existing `getCsrfFromSettingsPage()` helper, already used identically by other tests in the same file
- [#1853](https://github.com/elan-registry/registry/issues/1853) — test: fixed 4 pre-existing Playwright test-side bugs across `admin-unverified-account-cleanup.spec.js`, `navigation.spec.js`, and `security/datatables-xss.spec.js` — a strict-mode locator collision (scoped by id instead of name), a stale UI-wording assertion, and two XSS render-guard tests that never actually executed their check (root cause: DataTables serverSide tables never render `table.row.add()`-created rows regardless of page/search state — fixed by calling each column's render function directly instead)
- [#1854](https://github.com/elan-registry/registry/issues/1854) — test: `length-validation.spec.js`'s 24 tests against `chassis-availability.php`/`transfer-request.php` were all vacuous — Playwright's `data:` option serializes as JSON, but both endpoints only read `$_POST` (form-encoded); fixed by switching to `form:`. Uncovered and fixed a second, real bug while verifying: `transfer-request.php`'s 16 `CarTransferException` throw sites never set the exception's user-facing message (only the technical/log message), so the API always returned a generic fallback regardless of the actual failure reason — see the user-facing fix above
- [#1846](https://github.com/elan-registry/registry/issues/1846) — test: 2 of 7 tests in `car-edit-text-save.spec.js` failed with "page.route: Target page ... has been closed" — a downstream symptom, not the real bug. Both waited up to 10s for FilePond to hydrate an existing image via a mocked `fetchImages` response, but `fetchImages` only fires when `edit.php` renders in real update mode (only reachable via a POST, never the `car_id` GET query param these tests used), so the wait was structurally guaranteed to time out and race against Playwright's own 30s test-timeout teardown. Fixed by removing the doomed wait from one test (its actual assertions don't depend on hydration); the other test now performs a genuine POST into update mode against a real existing car (`CAR_ID_WITH_HISTORY`), relying on `TEST_USERNAME`'s Administrator permissions to bypass ownership, and asserts against dynamically-captured real hydrated filenames instead of a mocked value — a first attempt at fixing this test with a `test.skip()` guard based on a GET-navigation state check was caught by PR review as permanently, unconditionally skipping regardless of environment, and corrected before merge
- WIP: [#1443](https://github.com/elan-registry/registry/issues/1443) — ci: run Playwright browser tests in CI (de-MAMP the suite first)
